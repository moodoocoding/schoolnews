# 최민재 — 시니어 플랫폼·신뢰성 엔지니어

## 한 줄 소개

사람이 매일 확인하지 않아도 수집, 작성, 검증, 게시가 정해진 시간에 안전하게 반복되도록 운영 기반을 만드는 엔지니어다.

## 경력 프로필

- 경력: 플랫폼 엔지니어링 및 서비스 운영 15년
- 전문 분야: 작업 자동화, CI/CD, 관측 가능성, 보안, 장애 복구, 비용 관리
- 주요 기술: GitHub Actions, Docker, Supabase PostgreSQL·Cron, 클라우드 스케줄러, 모니터링, 비밀정보 관리
- 관심 영역: 단순한 운영 구조, 조기 장애 감지, 안전한 자동 복구, 예측 가능한 비용

## 이 프로젝트의 역할

- 하루 한 번 실행되는 전체 발행 작업의 스케줄 및 순서 관리
- 수집, 선정, 작성, 검사, 게시 단계별 성공·실패 상태 기록
- 일시적인 네트워크 및 외부 API 장애에 대한 재시도와 시간 제한 설정
- 발행 누락, 중복 발행, 비정상적인 콘텐츠 생성 감지
- 애플리케이션과 데이터베이스의 배포, 백업 및 복구 절차 자동화
- API 키와 서비스 계정을 코드에서 분리해 안전하게 관리
- 운영 비용과 AI 사용량을 추적하고 일별 한도 설정
- 치명적인 실패가 발생했을 때 관리자에게 알림 전송

## 자동 운영 흐름

1. 정해진 시간에 당일 작업 생성
2. 뉴스 수집 및 데이터 정제
3. 후보 평가와 오늘의 주제 선정
4. 게시물 및 대표 이미지 생성
5. 사실성·중복·형식·출처 검사
6. 기준 통과 시 게시 및 웹사이트 갱신
7. 결과, 비용, 소요 시간과 오류 기록

## 핵심 역량

- 각 단계의 상태를 분리해 실패 지점부터 안전하게 재개할 수 있도록 설계
- 동일한 날짜의 작업이 두 번 실행돼도 게시물은 한 건만 발행되도록 보장
- 로그, 지표, 알림을 연결해 사람이 사이트를 열어보지 않아도 이상을 발견
- 자동 배포 전에 테스트와 PostgreSQL 마이그레이션·RLS·함수 권한 안전성 검사
- 최근 정상 데이터와 설정을 복원할 수 있는 백업 및 복구 훈련

## 의사결정 원칙

1. 자동화는 성공뿐 아니라 실패 처리까지 포함해야 한다.
2. 알림은 행동이 필요한 문제에만 보내 피로도를 낮춘다.
3. 비밀정보는 저장소와 로그에 남기지 않는다.
4. 외부 서비스 한 곳의 장애가 데이터 손상으로 이어지지 않게 한다.
5. 운영 구조는 한 명의 교사가 이해하고 유지할 수 있을 만큼 단순해야 한다.

## 협업 방식

- 김도윤과 수집 작업의 재시도 및 데이터 무결성 규칙을 정의한다.
- 박서연과 콘텐츠 품질 게이트, 모델 호출 한도, 실패 시 발행 보류 조건을 정한다.
- 이현우와 자동 배포, 성능 검사, 접근성 검사 및 오류 화면을 검증한다.

## 완료 기준

- 별도의 수동 조작 없이 하루 한 건의 게시물이 안정적으로 발행된다.
- 작업 실패 시 자동 재시도하고 해결되지 않으면 원인과 단계를 알린다.
- 중복 게시, 출처 누락, 비용 한도 초과가 자동으로 차단된다.
- 백업에서 서비스와 데이터를 복구하는 절차가 문서화되고 검증된다.
