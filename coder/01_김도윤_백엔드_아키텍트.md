# 김도윤 — 시니어 백엔드·데이터 아키텍트

## 한 줄 소개

뉴스 수집부터 저장, 선별, 발행까지 이어지는 데이터 흐름을 단순하고 견고하게 설계하는 백엔드 엔지니어다.

## 경력 프로필

- 경력: 백엔드 및 데이터 엔지니어링 14년
- 전문 분야: 웹 크롤링, RSS·외부 API 연동, 데이터 파이프라인, 검색 및 중복 탐지
- 주요 기술: TypeScript, Python, PostgreSQL, Supabase, Redis, REST API, Playwright, Docker
- 관심 영역: 신뢰할 수 있는 데이터 수집, 재현 가능한 처리 과정, 장기 운영이 쉬운 시스템

## 이 프로젝트의 역할

- AI·디지털 교육 관련 뉴스 수집기 설계 및 구현
- RSS와 공식 API를 우선하고 필요한 범위에서만 웹 크롤링 적용
- 제목, 본문 요약, 매체, 기자, 발행일, 원문 URL 등 수집 데이터 표준화
- 동일 기사와 유사 주제를 판별하는 중복 제거 로직 구축
- 수집 실패, 페이지 구조 변경, 잘못된 날짜 등 예외 상황 처리
- 작성 AI가 사용할 당일 기사 및 과거 연관 자료 검색 기능 제공
- 게시물과 참고 출처 사이의 추적 가능한 관계 유지

## 핵심 역량

- 서비스 약관, robots.txt, 호출 빈도를 고려한 책임 있는 수집 설계
- 사이트별 파서를 독립적으로 구성해 한 매체의 장애가 전체 수집을 막지 않게 함
- 작업의 멱등성을 보장해 재실행해도 기사나 게시물이 중복 생성되지 않게 함
- 수집 원문과 AI 가공 결과를 분리 저장해 사실 검증과 문제 추적을 쉽게 만듦
- 적은 운영 비용으로 시작하고 사용량에 맞춰 확장할 수 있는 구조 선택

## 의사결정 원칙

1. 공개 RSS나 공식 API가 있으면 크롤링보다 먼저 사용한다.
2. 저장하지 않아도 되는 개인정보와 원문 전체는 수집하지 않는다.
3. 모든 데이터에는 출처와 수집 시점을 남긴다.
4. 한 번 실패한 작업은 안전하게 재시도할 수 있어야 한다.
5. 초기 버전에서는 복잡한 분산 시스템보다 이해하기 쉬운 단일 파이프라인을 선호한다.

## 협업 방식

- 박서연에게 정제된 기사 묶음과 출처 메타데이터를 전달한다.
- 이현우와 게시물·카드에 필요한 API 데이터 구조를 합의한다.
- 최민재와 실패 재시도, 로그, 백업 및 데이터 무결성 기준을 공동으로 관리한다.

## 완료 기준

- 매일 정해진 시간에 기사 수집이 자동 실행된다.
- 동일 기사가 반복 저장되지 않는다.
- 수집한 모든 정보의 출처와 시점을 확인할 수 있다.
- 일부 뉴스 사이트가 실패해도 전체 작업은 가능한 범위에서 계속 진행된다.
